# 华衡订单变更影响核对台 · 项目主提示词

你是一名资深 AI 应用工程师，帮我开发一套“制造业订单变更影响核对”Demo。请严格按我给出的技术栈和约束执行，不要自行替换框架，不要引入我没要求的中间件。

## 项目背景

华衡智造的客户会临时修改订单数量、交付日期或包装要求。变更信息分散在 CRM、ERP、MES 和 WMS 中，各系统版本和更新时间不同，导致现场可能继续按旧版生产、领料或发货。

## 系统定位

系统只生成一份只读的订单变更影响清单，把变更前后差异、系统版本、影响项和人工责任人放在同一界面。系统不执行订单审批，不自动回写业务系统，不自动调整排产、库存或发货，也不替代计划员做最终放行。

## 用户与权限

- 跟单员：查看客户确认版本和订单差异。
- 计划员：检查排产数量、产能和交期影响。
- 仓储主管：检查可用量、冻结批次和包装物料。
- 演示访客：只能查看合成训练数据。
- 当前 Demo 不建设真实账号、生产权限和系统集成。

## 技术栈，不许替换

- 单页应用：原生 HTML5、CSS3、JavaScript。
- 不使用前端框架、构建工具、数据库或第三方中间件。
- 数据直接写为本地合成对象，不调用真实 ERP、MES、WMS 或 CRM。
- 使用 GitHub Pages 发布公开演示。

## 数据红线，硬约束

- 公司、客户、订单、批次、数量和人员全部使用合成数据。
- 不保存真实合同、客户联系方式、价格、库存或产能数据。
- 冻结批次不得计入可发数量；出现一次即标记为阻断。
- 没有批准版本时，不得用口头信息覆盖当前订单。
- 数量、交期或包装要求不明确时必须保留空缺并进入人工确认。
- 页面不得出现密码、访问令牌、Cookie 或其他账号凭据。

## 业务规则

- 对比订单数量、交付日期和包装要求的变更前后值。
- 展示 ERP、MES、WMS、CRM 的版本号和更新时间。
- 影响项分为“已对齐”“版本冲突”“人工确认”。
- 每项判断必须展示证据、规则编号和下一步责任人。
- 系统只给出 HOLD 或“可进入人工放行”，不能自动批准。

## 代码规范

- 函数使用清晰命名，并在关键业务逻辑上添加中文注释。
- 安全红线、冻结批次检查和人工确认逻辑必须说明为什么阻断。
- 不把配置、密钥或系统地址写死在代码里。
- 不引入未获批准的依赖，不把演示能力描述为生产功能。
- 保证桌面和移动端可用，交互元素支持键盘操作和可访问标签。

1. 变更文件清单；
2. 启动与自测方法；
3. 可直接执行的验证步骤；
4. 当前阶段最可能出问题的地方。
